# Picking System

셀피아 주문 데이터를 수집해서 내부 피킹/검품/부족수량/배송보류 작업을 관리하고, 필요한 결과를 다시 셀피아 또는 우체국 양식으로 내보내기 위한 회사 내부 작업 시스템입니다.

현재는 GitHub Pages로 테스트 링크를 공유할 수 있도록 구성되어 있으며, 메인 시스템은 `index.html`과 `picking-system_0511.css`를 기준으로 동작합니다.

## 1. 주요 파일

### `index.html`

메인 피킹 시스템 화면입니다.

주요 기능:

- 셀피아 주문 데이터 로드
- 작업순서 정렬
- 피킹 체크
- 미송/부족수량 처리
- 배송보류 표시
- 골드상품 분리
- 검품탭
- CS탭
- 출력대상 CSV 내보내기
- 우체국 양식 CSV 내보내기
- 키패드 입력
- 서랍번호 입력

### `picking-system_0511.css`

메인 피킹 시스템 스타일 파일입니다.

주요 역할:

- 피킹 화면 레이아웃
- 좌측 조 목록
- 중앙 피킹 리스트
- 우측 상세 패널
- 하단 조별 주문서
- 검품/CS/모달/키패드 UI 스타일
- 완료/부족/보류/골드상품 색상 구분

### `sellpia_bookmarklet_v3.html`

셀피아에서 주문 데이터를 수집하기 위한 북마클릿 파일입니다.

주요 역할:

- 셀피아 재고매칭/주문 관련 화면에서 주문 데이터 수집
- 상품명, 옵션명, 수량, 자사코드, 주문번호, 송장번호 등 수집
- Supabase DB 저장 또는 업데이트
- 향후 우체국 양식에 필요한 수취인 정보 보강 기능 추가 예정

### `sellpia_memo_updater_v4_bookmarklet.html`

셀피아에 관리메모/관리메모2/배송보류 상태를 반영하기 위한 북마클릿 파일입니다.

주요 역할:

- 내부 피킹 시스템의 부족수량/서랍번호/보류 정보를 셀피아에 반영
- 관리메모, 관리메모2 업데이트
- 배송보류 설정/해제
- 반영 전 미리보기 구조
- 반영 결과 로그 관리

## 2. 현재 기본 작업 흐름

1. 셀피아에서 주문 데이터 수집
2. Supabase DB에 주문/상품 데이터 저장
3. 피킹 시스템에서 오늘 주문 로드
4. 작업순서 정렬
5. 피킹/부족수량/배송보류/골드상품 처리
6. 검품탭에서 주문별 확인
7. 출력대상 CSV 또는 우체국 양식 CSV 내보내기
8. 셀피아 메모 업데이터로 결과 반영

## 3. 작업순서 정렬 기준

현재 기본 작업 기준은 `작업순서`입니다.

정렬 기준:

1. 일반 주문 먼저
2. 골드상품 포함 주문은 뒤로
3. 상품종류 수가 적은 주문 먼저
4. 같은 상품종류 수라면 총수량이 적은 주문 먼저
5. 그래도 같으면 기존 순서 유지

목적:

- 1종/2종 주문을 먼저 처리해서 작업 속도 향상
- 골드상품은 일반 피킹 흐름과 분리
- 송장 출력순서와 피킹/검품 순서를 맞추기 쉽게 관리

## 4. 구역순 처리 상태

기존에는 구역순 피킹을 중심으로 고려했으나, 테스트 결과 송장 출력순서를 원하는 작업순서대로 맞출 수 있음을 확인했습니다.

현재 방향:

- 기본 작업 기준은 `작업순서`
- 구역순은 메인 흐름에서 제외
- 구역순 관련 기능은 완전 삭제하지 않고 보조 기능 또는 숨김 처리

## 5. 골드상품 처리

골드상품은 일반상품과 별도 피킹하는 상품입니다.

현재 처리 방식:

- 일반 피킹탭에서는 골드상품 행이 흐리게 표시됨
- 일반 피킹탭에서는 골드상품 체크 비활성화
- 일반 피킹 진행률/완료수 계산에서 골드상품 제외
- 골드상품 탭에서는 기존처럼 체크 가능

향후 개선:

- 일반 피킹 상태와 골드 피킹 상태를 DB 구조상 분리 검토
- 예: `pick_type`, `normal_pick_status`, `gold_pick_status`

## 6. 키패드 입력

현재 키패드는 화면 클릭뿐 아니라 실제 키보드/숫자패드 입력도 지원합니다.

지원 키:

- 숫자키
- 넘패드 숫자키
- Backspace
- Delete
- Enter
- Escape

입력 규칙:

- 수량/부족수량: 숫자 위주
- 서랍번호: 문자 입력 가능
- input/textarea 포커스 상태에서는 기본 입력 방해하지 않음

## 7. CSV 내보내기

### 출력대상 CSV

작업순서대로 송장 출력 대상을 확인하기 위한 CSV입니다.

용도:

- 현재 작업순서 확인
- 송장 출력 순서 맞추기
- 상품종류/총수량/골드포함/부족/보류 상태 확인

### 우체국 양식 CSV

우체국 공식 양식에 맞춰 내보내는 CSV입니다.

현재 헤더:

```csv
운송장번호,주문번호,주문일자,주문품목No,판매처상품명,판매처옵션명,주문수량,수취인명,수취인연락처,수취인핸드폰,우편번호,주소,주문메모
```

주의:

- 현재 재고매칭탭 데이터만으로는 주소/연락처/우편번호가 부족할 수 있음
- 실제 우체국 업로드용으로 사용하려면 셀피아 주문조회/주문원본에서 수취인 정보를 추가 수집해야 함
- 우체국정보 보강 기능 추가 필요

## 8. 우체국정보 보강 필요

우체국 양식 CSV를 실제로 사용하려면 아래 정보가 DB에 있어야 합니다.

필요 필드:

- 수취인명
- 수취인연락처
- 수취인핸드폰
- 우편번호
- 주소
- 주문메모
- 주문일자
- 주문품목No

추천 흐름:

1. 재고매칭 데이터 수집
2. 작업순서 정렬
3. 셀피아 주문조회/주문원본에서 수취인 정보 보강
4. Supabase orders 테이블 업데이트
5. 우체국 양식 CSV 내보내기

## 9. Supabase / DB 관련 주의사항

현재 일부 브라우저 코드에서 Supabase에 직접 접근하는 구조가 남아 있습니다.

주의:

- GitHub Pages 등 공개 링크에 올릴 경우 HTML/JS 코드가 보일 수 있음
- service_role key는 절대 브라우저 코드에 넣으면 안 됨
- anon/publishable key도 RLS와 권한 제한이 필요함
- 운영용으로는 브라우저에서 DB에 직접 접근하지 않고 API 서버 또는 NAS API를 거치는 구조가 안전함

향후 권장 구조:

```text
브라우저 화면
-> 내부 API / NAS API
-> PostgreSQL 또는 Supabase
```

## 13. 이후 확장 방향: 미송피킹 → 검품 → CS 연동

현재 시스템은 피킹 중심으로 기능이 정리되어 있지만, 이후에는 `미송피킹`, `검품`, `CS`까지 하나의 흐름으로 연결하는 것이 필요합니다.

목표는 피킹 단계에서 발생한 부족/미송/보류 정보를 다음 단계로 계속 넘겨서, 작업자가 같은 내용을 여러 번 확인하거나 다시 입력하지 않도록 하는 것입니다.

### 전체 흐름

```text
일반 피킹
-> 미송피킹
-> 검품
-> CS
-> 셀피아 메모/배송보류 반영
```

### 1) 미송피킹 연동

피킹 중 부족수량이 발생한 상품은 미송피킹 단계로 넘어가야 합니다.

필요한 흐름:

- 일반 피킹에서 부족수량 입력
- 부족수량이 있는 상품은 미송피킹 목록에 자동 표시
- 미송피킹에서 실제 추가 확보 여부 확인
- 확보되면 부족수량 조정 또는 해제
- 확보되지 않으면 검품/CS 단계로 미송 상태 유지

미송피킹에서 확인할 정보:

- 상품코드
- 상품명
- 옵션명
- 부족수량
- 원래 주문수량
- 송장번호
- 주문번호
- 수취인
- 서랍번호
- 메모
- 골드상품 여부

### 2) 검품 연동

검품탭은 최종 포장 전 확인 단계입니다.

필요한 흐름:

- 피킹 완료된 주문을 검품탭에서 확인
- 미송/부족/보류가 있는 주문은 검품 화면에서 명확히 표시
- 라벨번호가 있는 경우 검품탭에도 동일하게 표시
- 상품 수량이 여러 개여도 검품탭에서는 주문/상품 행을 과도하게 쪼개지 않음
- 필요한 경우 한 행에 라벨번호를 묶어서 표시

예시:

```text
상품A / 총수량 3 / 라벨번호 월1, 월2, 월3
```

검품탭에서 확인할 정보:

- 출력순번 또는 작업순번
- 송장번호
- 주문번호
- 수취인
- 상품코드
- 상품명
- 옵션명
- 주문수량
- 피킹완료 여부
- 부족/미송 여부
- 배송보류 여부
- 라벨번호
- 서랍번호
- 메모

### 3) CS 연동

검품 또는 미송피킹 단계에서 처리 불가능한 건은 CS 단계로 넘어가야 합니다.

CS로 넘어가는 경우:

- 미송 확정
- 부족수량 미해결
- 배송보류 필요
- 주문메모 확인 필요
- 고객 안내 필요
- 옵션/상품 불일치
- 주소/연락처 문제
- 기타 작업자 확인 필요

CS탭에서 필요한 기능:

- CS 대상 주문 목록 표시
- 미송/부족/보류 사유 표시
- 셀피아에 반영할 관리메모/관리메모2 내용 확인
- 배송보류 설정 여부 확인
- 처리완료/보류중 상태 관리
- 메모 복사 또는 셀피아 반영 기능과 연결

### 4) 상태값 연결

각 단계가 따로 움직이면 중복 확인이 많아지므로, 상태값을 공통으로 관리하는 것이 좋습니다.

추천 상태 흐름:

```text
picked
shortage_qty
misong_status
inspection_status
cs_status
hold_status
memo_update_status
```

예시 상태:

```text
피킹완료
미송대상
미송확정
검품대기
검품완료
CS필요
CS처리중
CS완료
셀피아반영대기
셀피아반영완료
```

### 5) 최종 목표

미송피킹, 검품, CS를 따로 보는 것이 아니라 하나의 작업 흐름으로 연결합니다.

```text
피킹에서 부족 입력
-> 미송피킹에서 재확인
-> 검품에서 최종 확인
-> CS에서 고객/보류/메모 처리
-> 셀피아에 결과 반영
```

이렇게 연결하면 부족수량, 배송보류, 관리메모 반영 과정에서 누락이나 중복 입력을 줄일 수 있습니다.
